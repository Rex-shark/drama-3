# spec — 專案規範文件

本目錄放**相對穩定**的專案文件與規範，與 `plan/`（持續變動的開發計畫）區隔：

- `plan/` 回答「接下來要做什麼、做到哪了」（動態、會頻繁更新）
- `spec/` 回答「這個專案的規則與事實是什麼」（穩定、變動較慢）

---

## 建議放置內容

| 檔案 / 目錄 | 用途 |
|------|------|
| `architecture.md` | 系統組成、資料流、設計決策、啟動方式 |
| `model-capabilities.md` | Drama 3 能力範圍（做 / 不做）、三個版本、控制語法、限制 |
| `api-conventions.md` | 後端 API 契約：端點、欄位、錯誤碼、MOCK 模式 |

本專案無資料庫，故無 `db/erd.mmd`。

---

## 維護原則

- 規範變更時即時更新對應檔案，避免文件與實作脫節。
- 新增資料表 / 改 Schema → **同步更新** [`db/erd.mmd`](db/erd.mmd)，使圖與實際 Schema 一致。
- `db/` 可依**功能模塊**判斷複雜度拆成子資料夾（例如 `db/auth/`、`db/order/`），
  避免單一 ERD 過於龐雜；模塊單純時維持單一檔案即可。
- 與 `plan/` 的踩雷紀錄互補：踩雷是「事故紀錄」，spec 是「最終正確做法」。
